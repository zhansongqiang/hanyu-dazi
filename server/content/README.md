# content.json —— 首版课程内容

内容写死在文件里，不做内容后台：五天做不出编辑器，而「扩充内容」是数据活，不是开发活。
改这个文件 → 重跑导入 → 重启后端，就是全部流程。

## 结构

```
units[]                        单元：level（basic/advanced/extended）× type（char/word/sentence/dialogue）
  └ lessons[]                  课时：一课时大约 5–10 分钟，对应「每天一刻钟」的节奏
      └ points[]               知识点：一个字 / 一个词 / 一句话
```

**数组顺序就是学习顺序**：导入脚本按位置写 `sort`（第 1 个是 1，依次往后），
所以调整顺序就是把条目上下移动，不用手工改数字。

## 知识点字段

| 字段 | 说明 |
| --- | --- |
| `key` | 稳定标识，纯 ASCII。音频文件名、去重、内容改动时的对齐都用它，**改名等于换一个知识点** |
| `text` | 学的东西本身：`日` / `老师` / `你好` |
| `pinyin` | 带声调。词与句用空格分词：`nǐ hǎo` |
| `gloss` | 英文释义（面向留学生，选词义题的选项就是它） |
| `hint` | 中文小提示，答题反馈与描红页会用；没有就不显示 |
| `kinds` | 这个知识点出哪几种题（见下）。不写就继承所属 lesson 的 `kinds` |

## 题型的五种取值

| kind | 形态 | 数据来源 |
| --- | --- | --- |
| `recognize` | 认字：给汉字，选拼音 | `text` + `pinyin` |
| `pinyin` | 拼音：给拼音，选汉字 | `text` + `pinyin` |
| `meaning` | 词义：给汉字，选英文意思 | `text` + `gloss` |
| `listen` | 听音选字：给音频，选汉字 | 需要音频文件在位，否则这条不出 |
| `stroke` | 笔顺：米字格描红 | 只给 12 个象形字（`text` 是单字） |

跟读录音（**争取项**，收尾日）不新增题型：它就是挂在 `listen` 题上的另一个入口 ——
同一段音频、同一个词，先「听音选字」再「跟着说一遍」，录音记在 `recordings.item_id` 上。
所以现在不必为它预留 kind，Day 5 做不做都不动这个文件。

## 由谁展开成 items

`content.json` 里**没有选择题的选项**。选项由导入脚本按规则生成：

- 每个知识点按 `kinds` 展开成若干条 `items`，`answer` 取自知识点本身；
- 干扰项从**同一个 lesson 的兄弟知识点**里取，不够再向同 unit、同 level 扩；
  这样干扰项天然同质（选拼音时不会混进英文，选词义时不会混进无关类别）；
- 取法由知识点 `key` 做确定性打散 —— 同一次导入永远得到同一组选项，
  不会出现「刷新一下正确答案变了」。

## 音频

约定文件名 `content/audio/<key>.mp3`（如 `ri.mp3`、`nihao.mp3`）。
导入时文件在就写 `audio_url`，不在就留空、`listen` 题不出。
音频用 edge-tts 预生成（不用运行时浏览器合成：安卓 WebView 支持不全，中文本地音色不稳）。
`content/audio/` 与 `content.json` 一起部署，后端以静态目录挂在 `/audio` 下提供。
