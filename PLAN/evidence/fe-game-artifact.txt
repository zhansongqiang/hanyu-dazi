### 2. 怎么做到"验产物但不碰共享库"

产物是静态文件，但它要打后端。共享 dev 后端（8091）接着**共享库**，往里面写取证账号会污染
别人的数据。做法是老三样（与 `fe-game-edge.txt` 同源）：

    # ① 在线快照：不停任何进程、不碰共享库
    cd server && npx tsx .snap-art.ts
    # → SNAP_OK bytes=274432      （→ server/data/tmp-art.db，无 -wal 伴随文件）

    # ② 隔离后端：自己的端口、自己的库副本、不跑 migration
    PORT=8099 HOST=127.0.0.1 DB_FILENAME=./data/tmp-art.db AUTO_MIGRATE=false npx tsx src/index.ts

    # ③ 静态分发产物，并把代理改指 8099
    cd mobile && npx vite preview --config vite.preview.config.ts     # → 127.0.0.1:4173

`vite preview` 默认继承 `server.proxy`，而 `vite.config.ts` 里的代理指向**共享的 8091** ——
所以临时配置 `vite.preview.config.ts` 把 `/api`、`/audio`、`/uploads` 三个前缀重指到 8099。
**本路全程没有向 8091 发过一个请求**，共享库与别人的文件一个字节没动。

### 3. 断言怎么算数

- 只统计 `new URL(u).pathname` 以 `/api/` 开头的请求（`/audio`、`/uploads` 不计入「N 个请求」）；
- 同时监听 `console` 的 `type === 'error'` 与 `pageerror` —— Vue 的渲染期错误**只走 console.error**，
  只监听 `pageerror` 会漏（这是本项目踩过的坑）；
- 登录态注入：**直接写 `localStorage`**，原因见下面的 P0b。

## P0b · 产物里 `window.uni` 是个空壳（**给后来人省一天**）

注入登录态时第一版用了 `uni.setStorageSync`（dev server 下能用），在**产物里直接崩**：

```
TypeError: window.uni.setStorageSync is not a function      （第一次跑，exit=2）
```

探针实测产物页里 `window.uni` 的形状：

```
[P0b] {"hasUni":"object","uniKeys":0,"uniSample":[],"setStorageSync":"undefined","lsKeys":[]}
```

**结论**：H5 产物里 `window.uni` 是 `{}`（**0 个键**），`setStorageSync` 是 `undefined`；
产物 bundle 里也**搜不到** `StorageSync` 字样。真实存储是**模块内部**的，落在 `localStorage` 上，
写入格式是 uni 自己的包装：

    localStorage.setItem(key, typeof v === 'string' ? v : JSON.stringify({ type: typeof v, data: v }))

读的时候校验 `{type, data}` 再把 `data` 取出来。所以注入必须**绕开 `window.uni`**、
按这个包装格式直接写 `localStorage`，键名就是 `token` 与 `userInfo`。

顺带一个坑：uni 的 `<input>` 带 `placeholder-class` 时，**占位文字不是 `<input>` 的属性** ——
它被渲染成一个**兄弟节点** `div.uni-input-placeholder`，内层 `<input class="uni-input-input">`
上**没有** `placeholder` 属性。所以断言占位文字时读 `input[placeholder]` 会拿到 `null`
（我第一版就是 `null`，靠单独写了一个探针 dump 真实 DOM 才定位到）。

## 本文件**没有**覆盖的（写明白，别让复核的人误以为都验过）

- **真机 / WebView**：本轮浏览器是 **chromium 1208（桌面引擎）**，不是真机、不是 WebView。
  本项目在移动端的已知坑（iOS 软键盘顶起、tabbar 遮挡底部按钮一类）**不在覆盖面内**，
  详见 CLAUDE.md 里那条 iOS 清单。
- **APK**：本轮验的是 **H5 产物**（`uni build` 的 h5 目标）。**没有**打 APK，也没有装到手机上跑。
  "打包"在本项目里有两条腿（H5 dist / APK），本轮只走了 H5 那条。
- **游客"答完并交卷"在产物上没重跑**：见 P2 的诚实边界，那条路径的证据在接口侧文件里。
- **P3b / P5 的夹具是直接写库注入的**：写的是**临时库副本** `server/data/tmp-art.db`，
  **共享库一个字节没动**。它们验的是"页面/接口对这份数据的反应"，不是"系统会自动产生这份数据"。
- **并发**：所有断言都是单进程顺序跑，没有并发压测。
