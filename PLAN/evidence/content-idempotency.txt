结论：**第 2、3、4 遍导入一律「新增 0」（单元/课时/题目/印章四项全部为 0），
items 全表指纹三次不变，`content-audit` 退出码 0、0 问题**

## 命令 —— **全新的**一次性库上跑，不碰共用开发库

用新库而不是复用旧库，是因为「幂等」要说的是「从零建起来也是这样」，
在一个已经被改过很多轮的库上验，说明不了这条。

    $ cd server
    $ rm -f data/_c4.db*
    $ export DB_FILENAME=./data/_c4.db
    $ npx tsx src/migrate.ts                       # exit=0，5 个迁移文件，batch 1
    $ npx tsx scripts/import-content.ts            # 第 1 遍
    $ npx tsx scripts/import-content.ts            # 第 2 遍
    $ npx tsx scripts/import-content.ts            # 第 3 遍
    $ npx tsx scripts/content-audit.ts             # exit=0

## 幂等的第二层：选项也得一字不差

「新增 0」只说明**行数**没涨。如果干扰项打散退化成随机，行数照样不涨，
但用户复习时会看到另一组选项（内容没改，题目却像换了）——这一层得单独量。

第 3 遍之后与第 4 遍之后，取 `items` 全表（`id + point_key + kind + options + answer + sort + hint`）
的 md5：

    第 3 遍后：46aa0ee9baa74492ad01cfb626ae50c9   题数 296
    第 4 遍后：46aa0ee9baa74492ad01cfb626ae50c9   题数 296

指纹相同 ⇒ 选项、答案、题序全部原样。同一份证据里还能直接看到：三遍导入打印的
「抽查」五行选项也逐字相同（`["rì","yuè","huǒ","shuǐ"]` / `["火","水","日","月"]` / …）。

## content.json 合法 + 校验 0 错误

    $ npx tsx scripts/content-audit.ts
    校验和 77b03ed4ae0e63a8（重跑导入后应保持不变）

    没有发现问题。
    audit exit=0

抽检的不变量（导入器本该保证、这里独立复核）：选项 4 个、正确答案在选项里、选项不重复、
描红题有 `char` 且是单字、听音题有 `audio_url` 且题干不写答案、每题都有 `prompt_en`。
76 个知识点全部写了 hint（`hint 非空 296/296`）。

## 一处需要说清的读数差异（不是缺陷）

同一个 `content-audit` 在**共用开发库**上跑，校验和是 `94dec8c8f1a5daae`，
在**全新一次性库**上是 `77b03ed4ae0e63a8`。查过了，是**行序**差异，不是内容差异：

| 排序方式 | 共用库 `hanyu-dazi.db` | 一次性库 `_c4.db` |
|---|---|---|
| 不写 orderBy（脚本现状） | `94dec8c8f1a5daae` | `77b03ed4ae0e63a8` |
| `order by id` | `94dec8c8f1a5daae` | `77b03ed4ae0e63a8` |
| `order by point_key, kind, id` | **`7c8410928a09712f`** | **`7c8410928a09712f`** |

按内容排序后两边**完全相同** ⇒ 同一份内容、同一个题集；差别只在 `id` 怎么分配。
共用库是好几轮内容改动累积起来的（按 key 更新、不删不重插，所以老题的 id 保留），
全新库则是照 content.json 的顺序一次插完 —— `id` 自然不同。

**这正是幂等设计要的效果**：`attempts.item_id` 指着 items，如果导入删了重插，
所有历史答题记录会指向不存在的题，错题本和进度当场变空、且用户侧没有任何报错。
所以校验和的正确用法是「**同一个库文件，改前改后比**」（脚本注释也是这么写的），
跨库比较得先按内容排序。
