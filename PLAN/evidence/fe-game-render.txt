## 这份文件补的到底是什么

前两份证据文件把「后端**会**下发什么」验透了，但 §8 的三条验收标准里有两条
**本身就是渲染问题**，接口侧证明了也不算数：

| §8 原话 | 接口侧能证明吗 | 本文件怎么证明 |
|---|---|---|
| G1「所有数字来自**一个** `GET /profile/summary`，不是 N 个请求凑」 | **不能** —— 要数的是**页面**发了几个请求 | 页面级请求监听 + 与页面文本逐字比对 |
| G2「自己上榜后能看到自己的名字」 | **不能** —— 「看到」是像素 | 榜单行的 DOM 类名 + 计算样式底色 |
| G3「未得的章**也显示**（灰态），不是只显示已得的」 | **不能** —— 灰态是 CSS | 15 枚印章的 `opacity` / `border-style` 实测计算值 |
| G5「分享链接未登录能打开」 | 部分能（接口不挂鉴权） | **无任何 storage 的干净上下文**打开分享 URL |
| G6「建队/入队能走通」 | 部分能（接口 code:0） | 两个视角各自上屏的成员归属 |

前两份文件里「仍未验的部分」列的三条（G2 前端 / G3 前端 / G5-G6 前端）**由本文件勾掉**。

## 环境与方法

- **工具链是借的，没装任何依赖**：复用本机 SmartCampus 的
  `D:/coding/SmartCampus/web/node_modules/playwright-core`（1.64.1，它期望 chromium **1248**），
  但用**显式 `executablePath`** 指向本机已有的 chromium **1208**
  （`C:/Users/Admin/AppData/Local/ms-playwright/chromium-1208/chrome-win64/chrome.exe`）。
  版本差 40，所以 `executablePath` 是必须的，不能靠 playwright 自己找。
- **只读使用共享进程**：页面走共享的 vite dev server `http://127.0.0.1:5173`（前端 + `/api` 代理），
  代理到共享后端 **8091**（PID 32800）。**本轮没有起 8099，也没有 kill 任何 dev server。**
- **造数据全部走公开接口**，不走 SQL 注入：账号用 `POST /auth/register`
  （**刻意不走 `/login`** —— 那个接口有 loginLimiter 每分钟 5 次）；对战用 `POST /duels`；
  组队用 `POST /teams` / `POST /teams/join`。
- **注入登录态的可靠手法**（hash 路由下 hash-only 导航**不会**重新加载页面，
  所以在同一 page 里改 hash 是测不到真实加载的）：
  在 context 里先开一个 boot page 到 `APP + '/'` 让 `window.uni` 就绪 →
  `page.evaluate(() => window.uni.setStorageSync('token'|'userInfo', …))` →
  关掉 boot page → **`newPage()` 到目标 hash URL（整页加载，localStorage 同 origin 可见）**。
  R3 的游客场景**反过来**：全新 context、一个字节 storage 都不写。
- **判「后端请求」的唯一判据**：`new URL(u).pathname.startsWith('/api/')`。
  这条判据是被一次**假阳性**逼出来的，见下一节。

### 一次假阳性（如实记录，它是判据的由来）

v1 脚本用 `u.split('/api')[1]` 找后端请求，跑出来报 G1 FAIL（"页面没有第二个取数请求"）。
**复盘结论：这是我自己的判据写糙，不是产品缺陷。** dev server 的源码模块与 uni-h5 的样式
全部命中了这个粗糙正则：`/src/api/user.ts`、`/src/api/checkin.ts`、`/src/api/xp.ts`、
`/src/api/index.ts`，以及 `…/api/modal.css`、`toast.css`、`action-sheet.css`、
`location-view.css`、`index.js`、`app.js`、`component.js`、`context.js`、`hooks.js`、`util.js`。
改成只认 `pathname` 以 `/api/` 开头之后，各页的后端请求集合收敛为：
R1 `["/profile/summary"]`、R2 `["/stamps"]`、R3 `["/duels/A59X6R"]`、R4 `["/rank/week"]`、
R5 `["/teams/mine"]` —— **每页恰好一个**。
